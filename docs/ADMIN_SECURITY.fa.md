# پنل ادمین، امنیت و سناریوهای مدیریت

این سند پایهٔ 0.2 است. بازبینی R02 نقص snapshot قدیمی در تغییر رمز خود کاربر را بازتولید کرده و R05 قرارداد retry چندتب را نیازمند اصلاح می‌داند. قرارداد امنیت هدف و ترتیب A02/A05 در [بازبینی](ARCHITECTURE_REVIEW.fa.md)، [معماری هدف](ARCHITECTURE_TARGET.fa.md) و [نقشهٔ اجرا](IMPLEMENTATION_ROADMAP.fa.md) آمده است؛ اصلاح runtime هنوز انجام نشده است.

نقش مدیریتی به enrollment تأییدشدهٔ MFA نیاز دارد. آخرین مالک فعال قابل تنزل یا غیرفعال‌سازی نیست؛ خودغیرفعال‌سازی رد می‌شود. سقف ۱۰ حساب با قفل مشترک شامل حساب غیرفعال است. حذف حساب برای آزادکردن ظرفیت از پنل وجود ندارد.

## ورود، تأیید مجدد و بازیابی

Fortify ورود را انجام می‌دهد. پس از رمز درستِ حساب دارای MFA، نشست authenticated ساخته نمی‌شود؛ challenge با عمر ۱۰ دقیقه و access_version جاری نگه‌داری می‌شود. OTP یا recovery معتبر مرحله را کامل می‌کند. وضعیت فعال‌بودن، enrollment و نسخهٔ دسترسی در لحظهٔ challenge دوباره خوانده می‌شود. مصرف recovery در تراکنش سری می‌شود. مسیر قدیمی ورود مستقیم و مسیر عمومی ثبت‌نام/بازیابی ایمیلی فعال نیستند.

فعال‌سازی نیازمند رمز تأییدشده و یک OTP درست است. secret و recovery در DB رمز شده‌اند. حساب مدیریتی نمی‌تواند MFA را از HTTP غیرفعال کند. خواندن/تولید کد بازیابی و نوشتن مدیریتی به تأیید هویت تازه نیاز دارد: حداکثر ۱۵ دقیقه برای رمز و، در حساب MFAدار، OTP. secret و recovery به Query cache، localStorage، audit یا Resource کاربر نمی‌روند. frontend کدهای بازیابی را تا اعلام ذخیره‌سازی نمایش می‌دهد.

تغییر نقش، وضعیت، رمز یا recovery اپراتوری، access_version را افزایش می‌دهد. نشست نسخهٔ قدیمی حتی اگر یک ردیف session از مسابقهٔ هم‌زمان باقی بماند رد می‌شود. reset رمز عضو توسط مدیر مجاز، تمام نشست‌های او را باطل می‌کند ولی MFA را خاموش نمی‌کند. تغییر رمز خود از تنظیمات با رمز فعلی است.

برای مالک قفل‌شده، روی میزبان مورد اعتماد و پس از احراز هویت خارج از برنامه:

```bash
php artisan app:recover-owner owner@example.com --reset-mfa
```

فرمان یک حساب موجود را به مالک فعال تبدیل و نشست‌هایش را باطل می‌کند؛ حساب یازدهم نمی‌سازد و رویداد ثبت می‌کند. `--reset-mfa` اختیاری است و کلیدها/تأیید فعلی را پاک می‌کند تا enrollment دوباره انجام شود. `--force` فقط تأیید تعاملی اپراتور CLI را حذف می‌کند. این فرمان endpoint مرورگر ندارد. دسترسی سیستم‌عامل/کلید اپلیکیشن بخشی از مرز اعتماد است.

## کنترل‌ها و مرز تضمین

| تهدید | کنترل اجرایی | شواهد/محدودیت |
| --- | --- | --- |
| CSRF / سرقت token از storage | session همان مبدأ، CSRF، cookie HttpOnly و secure در production | credential مرورگر در localStorage نیست؛ HTTPS باید روی سرور فعال شود |
| brute force / credential stuffing | rate limit حساب+IP، Timebox و پیام عمومی | محافظت edge و نظارت واقعی سرور جداست |
| عبور از MFA | pipeline Fortify، challenge سری و نسخه‌دار | تست HTTP رمز تنها، recovery یک‌بار، انقضا و غیرفعال‌سازی |
| privilege escalation | enum capability، Gate، actor تازه در Actionهای حساس | تست curator و administrator؛ نمایش UI مرجع امنیت نیست |
| از دست‌رفتن مالک | قفل و قاعدهٔ آخرین مالک | تست HTTP تنزل/غیرفعال‌سازی |
| IDOR رسانه | policy واحد metadata/cover/stream و private path | تست draft/archived و Range/HEAD |
| فایل جعلی / path traversal | حد اندازه، MIME واقعی، FFprobe timeout، نام تولیدشده و realpath | transcoding/آنتی‌ویروس pipeline فعلی نیست |
| SQL injection | binding و allowlist فیلترها | آزمون ورودی فیلتر audit؛ SQL مستقیم DBA خارج از مرز برنامه است |
| overwrite همزمان | revision و تراکنش | 409 و تست حفظ ترتیب/لایک/عضویت |
| تکرار job/import | unique idempotency و state تحت قفل | تست retry و rollback |
| افشای لاگ | request ID، metadata allowlist، عدم ثبت رمز/کلید | audit در سطح ORM از update/delete منع می‌شود؛ DBA می‌تواند SQL اجرا کند |
| وابستگی آسیب‌پذیر | lockfile و composer/npm audit در CI | نتیجه مربوط به زمان اجراست، تضمین نبود آسیب‌پذیری نیست |

هدرهای nosniff، DENY framing، Referrer-Policy، Permissions-Policy و CSP در production تنظیم‌اند. API no-store است. CSP فعلی style inline را برای component styles مجاز می‌گذارد؛ سخت‌گیری بیشتر نیازمند nonce/style refactor است. `/up` liveness است، readiness کامل نیست. صفحهٔ operations شمارش صف را با سلامت worker یکی نمی‌گیرد.

هدف بازبینی امنیت، ردیابی الزامات مناسب OWASP ASVS 5 سطح ۲ است؛ ممیزی مستقل یا گواهی انطباق انجام نشده. آزمون همزمانی چندپردازه، بازیابی backup، تست نفوذ، دستگاه واقعی و بار ۱۰ stream پیش از انتشار عملیاتی باقی‌اند.
