# طرح جامع آهنگ خط‌کش

## هدف و مرز محصول

هدف، ساخت کتابخانهٔ شخصی موسیقی با کیفیت تجربهٔ محصولات بین‌المللی است: ورود سریع، پیدا کردن موسیقی بدون اصطکاک، پخش پیوسته هنگام تغییر صفحه و مدیریت قابل اعتماد مجموعه‌ها. مخاطب یک گروه خصوصی با حداکثر ۱۰ حساب است. مدیران نیز داخل همین ظرفیت‌اند؛ غیرفعال‌کردن حساب ظرفیت جدید ایجاد نمی‌کند. تجربهٔ کاربری از ساختار آشنای پلیرهای موسیقی الهام می‌گیرد و هویت بصری خط‌کش را حفظ می‌کند.

در نسخهٔ حاضر، کاتالوگ منتشرشده میان تمام اعضای فعال مشترک است. علاقه‌مندی‌ها، پلی‌لیست‌های ذخیره‌شده، تم و وضعیت پخش شخصی‌اند. مدیران پیش‌نویس‌ها را هم می‌بینند. فایل‌های صوتی و کاور از پنل وارد می‌شوند؛ فایل‌ها روی دیسک خصوصی و اطلاعات توصیفی در دیتابیس نگهداری می‌شوند. این انتخاب، فرض اجرایی نسخهٔ اولیه است و باید پیش از افزودن دسترسی‌های گروهی در ADR جدید تغییر کند.

## نقش‌ها

چهار نقش owner، administrator، curator و listener با capability مستقل وجود دارند. مالک می‌تواند نقش ممتاز تعیین کند؛ مدیر اعضا و محتوا، مدیر محتوا کاتالوگ و import و شنونده فقط کتابخانهٔ منتشرشده را مدیریت می‌کند. جزئیات کنترل، MFA و آخرین مالک در [امنیت پنل](ADMIN_SECURITY.fa.md) است.

## صفحات و مسیرهای اصلی

| مسیر رابط | هدف | رفتار اصلی |
| --- | --- | --- |
| `/` | خانه | مجموعهٔ شاخص، فیلتر حال‌وهوا، کارت‌ها و تعداد آهنگ‌ها |
| `/search` | جستجو | نام آهنگ، هنرمند، آلبوم و پلی‌لیست؛ تطبیق حروف فارسی/عربی |
| `/library` | کتابخانهٔ من | مجموعه‌هایی که همین کاربر نشانک زده است |
| `/liked` | پسندیده‌ها | آهنگ‌های لایک‌شدهٔ همین کاربر و پخش صفحهٔ جاری |
| `/playlists/:id` | جزئیات | کاور، توضیح، مدت کل، ردیف‌ها، پخش همه و ذخیره |
| `/admin` | نمای کلی مدیریت | آمار واقعی و مسیر شروع کار |
| `/admin?tab=imports` | ورود موسیقی | آماده‌سازی، پیش‌نمایش، ساخت و سابقهٔ ایمپورت |
| `/admin?tab=catalog` | کاتالوگ | هنرمند، انتشار، اعتبار هنری و نسخهٔ اطلاعات |
| `/admin?tab=audit` | رویدادها | فیلتر و تاریخچهٔ تغییرات با cursor |
| `/admin?tab=operations` | وضعیت سیستم | تشخیص محدود DB/queue/FFprobe |
| `/admin?tab=security` | امنیت | MFA و کدهای بازیابی |
| `/admin?tab=library` | مدیریت مجموعه | ساخت، ترتیب آهنگ‌ها، ویرایش اطلاعات، وضعیت انتشار/بایگانی و کاور |
| `/admin?tab=users` | اعضا | ظرفیت، نقش، وضعیت و بازنشانی کنترل‌شدهٔ رمز |
| پنجرهٔ حساب | تنظیمات | تم روشن/تیره/دستگاه، تغییر رمز و خروج |
| پنجرهٔ صف پخش | مدیریت نوبت شنیدن | مشاهدهٔ ترتیب واقعی پخش و انتخاب آهنگ |

ناوبری SPA است؛ Audio در provider بالای صفحه‌ها قرار دارد. در نتیجه تغییر مسیر رابط، صوت را از ابتدا بارگذاری نمی‌کند.

## سناریوهای پذیرش

| شناسه | رخداد | نتیجهٔ مورد انتظار |
| --- | --- | --- |
| S01 | نصب تازه | بدون رمز ثابت و حساب عمومی؛ ساخت مدیر با CLI |
| S02 | ورود موفق | session جدید، CSRF معتبر و باز شدن کاتالوگ |
| S03 | ایمیل یا رمز نادرست | پیام یکسان و محدودیت تلاش برای ورود |
| S04 | ایجاد حساب دهم/یازدهم | دهم ثبت؛ یازدهم با خطای اعتبارسنجی رد می‌شود |
| S05 | ایجاد همزمان حساب | نوشتن روی ردیف قفل قبل از شمارش، ظرفیت را سری می‌کند |
| S06 | بارگذاری فایل تکراری | همان asset برمی‌گردد و فضای صوت دوباره مصرف نمی‌شود |
| S07 | manifest دارای ردیف نامعتبر | خطای ردیف و هیچ پلی‌لیست نیمه‌کاره‌ای ساخته نمی‌شود |
| S08 | پیش‌نمایش معتبر | فقط import آماده ایجاد می‌شود؛ هنوز کاتالوگ تغییر نمی‌کند |
| S09 | تأیید دوبارهٔ ایمپورت | یک job منطقی و یک پلی‌لیست؛ اجرای مجدد job بی‌اثر است |
| S10 | شکست worker وسط ساخت | تمام نوشتن‌های ساخت آن پلی‌لیست rollback می‌شوند |
| S11 | پخش و تغییر صفحه | آهنگ ادامه دارد و نوار پخش ثابت می‌ماند |
| S12 | seek در صوت | درخواست Range و پاسخ 206؛ بازهٔ نامعتبر پاسخ 416 |
| S13 | خاموش/روشن کردن shuffle | آهنگ جاری حفظ می‌شود؛ چرخهٔ shuffle آهنگ تکراری ندارد |
| S14 | repeat off / all / one | پایان صف متوقف می‌شود / چرخه برمی‌گردد / آهنگ جاری تکرار می‌شود |
| S15 | باز کردن برنامه در نوبت بعد | صف و موقعیت برمی‌گردند؛ پخش خودکار شروع نمی‌شود |
| S16 | تب قدیمی وضعیت را ذخیره کند | revision قدیمی با 409 رد و رابط پیام تازه‌سازی نشان می‌دهد |
| S17 | عضو draft را مستقیماً درخواست کند | جزئیات، کاور و صوت محافظت می‌شوند؛ شناسه مجوز نیست |
| S18 | عضو لایک یا نشانک بزند | رابطه شخصی است؛ دیگر اعضا تغییری در کتابخانهٔ خود نمی‌بینند |
| S19 | تغییر تم و ورود مجدد | انتخاب در حساب و مرورگر اعمال می‌شود؛ گزینهٔ دستگاه هم پشتیبانی می‌شود |
| S20 | غیرفعال شدن حساب | sessionهای دیتابیس حذف و درخواست بعدی محافظت می‌شود |
| S21 | تغییر رمز | رمز فعلی لازم است؛ رمز ذخیره‌شده hash است؛ session فعلی rotate می‌شود |
| S22 | قطع شبکه | رابط خطای قابل اقدام دارد؛ کاتالوگ یا فایل پخش‌شده با دادهٔ نمایشی جایگزین نمی‌شود |

S05 به اجرای رقابتی روی موتور هدف نیاز دارد. قفل و قیدهای لازم در کد وجود دارند؛ تست موازی واقعی MySQL هنوز یک شرط انتشار در برنامهٔ توسعه است. S11 تا S19 علاوه بر تست‌های خودکار موجود، آزمون مرورگر واقعی نیز لازم دارند؛ وضعیت انجام آن در سند بررسی مشخص است.

## کیفیت مورد انتظار

هر کلیک باید نتیجهٔ روشن، وضعیت انتظار، خطا و راه برگشت داشته باشد. حالت خالی بخشی از طراحی است. رابط موبایل منوی کشویی و کنترل پخش کامل دارد. تم روشن یک سیستم رنگ مستقل است. حرکت‌ها کوتاه‌اند و تنظیم کاهش حرکت رعایت می‌شود. اطلاعات دوزبانه با جهت خودکار نمایش داده می‌شود و زمان پخش LTR است.

هدف اولیهٔ ظرفیت، ۱۰ شنوندهٔ همزمان و حفظ پاسخگویی API است؛ این هدف معیار آزمایش ظرفیت آینده است، نه نتیجهٔ بنچمارک انجام‌شده. زمان پاسخ، مصرف RAM و رفتار Safari/Firefox/Chrome باید روی سرور و فایل‌های واقعی اندازه‌گیری شوند.
