# ادامهٔ توسعه و معیار پذیرش

## آنچه در نسخهٔ 0.2 اجرایی است

کتابخانهٔ خصوصی، فایل صوتی/کاور محافظت‌شده، JSON/CSV import و queue idempotent، کاتالوگ نرمال‌شده، چند اعتبار هنری، انتشار با دیسک/شماره، ساخت/ویرایش/ترتیب/بایگانی پلی‌لیست، role/capability، MFA واقعی، recovery، step-up، reset کنترل‌شدهٔ رمز عضو، audit cursor و overview/operations. تم روشن/تیره/سیستم، فارسی/RTL و player مستقل از route وجود دارند.

## گام بعدی پیشنهادی: staging واقعی

1. MySQL و phpMyAdmin را طبق راهنمای مخزن روی محیط توسعهٔ خود راه‌اندازی کنید؛ migration و ایجاد مالک را انجام دهید و MFA را با گوشی خود تأیید کنید.
2. دو پلی‌لیست با فایل‌های واقعی خود و دادهٔ هنرمند/انتشار مشخص وارد کنید؛ preview، retry، reorder، publish/archive و بازیابی صف را بررسی کنید.
3. میزبان staging، دامنه و فضای خصوصی رسانه را تعیین کنید؛ TLS، worker و backup را پیکربندی کنید. CI انتشار خودکار انجام نمی‌دهد.
4. روی staging آزمون همزمانی ظرفیت ۱۰ حساب و دو ویرایش همزمان، ده stream با seek، قطع worker/شبکه و ارتقای دادهٔ موجود اجرا شود. موفقیت معیارها ثبت شود، بدون جایگزین‌کردن عدد تخمینی با اندازه‌گیری.
5. backup دیتابیس، فایل و APP_KEY در محیط خالی بازیابی و نتیجه ثبت شود. RPO/RTO واقعی بعد از این آزمون تعیین شوند.
6. موبایل واقعی، Safari/Firefox/Chrome، zoom، screen reader، صفحه‌کلید و contrast ارزیابی شوند؛ کنترل‌های ASVS مناسب دامنه به شواهد وصل شوند.

## کارهای بعدی با نیاز مشخص

- preview تغییرات import به کاتالوگ و گردش بازبینی هویت‌های بازیابی‌شده؛ merge هنرمند فقط با انتخاب صریح و برنامهٔ نگاشت ارجاع‌ها.
- UI و انتخاب rendition، transcoding پایدار، loudness/waveform واقعی و X-Accel پس از اندازه‌گیری stream.
- عملیات orphan media با dry-run، حفظ ارجاع importهای آماده/درحال‌ساخت و دورهٔ نگهداری.
- مشاهدهٔ sessionهای دستگاه‌ها، passkey/WebAuthn و reset ایمیلی فقط با نیاز و زیرساخت ارسال معتبر.
- جستجوی بزرگ‌تر با دادهٔ واقعی و EXPLAIN، سپس تصمیم دربارهٔ FULLTEXT یا موتور مستقل.
- همکاری playlist یا تکرار یک Track در playlist نیازمند مدل occurrence و هویت جداگانهٔ queue entry است؛ v1 عمداً dedup دارد.

برای هر قابلیت جدید: سناریو و permission، migration جدید، Action/Resource، قرارداد OpenAPI، حالت‌های UI، آزمون رفتار و شواهد مرورگر لازم است. «افزودن الگوی معماری» بدون مشکل مشخص، هدف توسعه نیست.
